## Built for Fast-Moving AI Tooling

This handbook uses explicit verification labels because AI coding tools change quickly. `Verified`, `Locally tested`, `Documentation verified`, `Needs verification`, `Experimental`, account/plan constraints, and similar labels communicate how much confidence to place in a page before standardizing on it.

When a page includes a `Sources` section, treat those links as the evidence boundary for its claims.

The public issue queue is intentionally curated: starter issues should name the file, acceptance criteria, source expectations, and validation command. If the handbook saves you time, **star the repository** so you can find it again and more developers can discover it.
